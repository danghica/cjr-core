# Parametric polymorphism for CJR

## Summary

Add an explicitly parameterised source language that supports generic functions, classes, structs, and methods. Erase it into the existing CJR operational language for Iris verification, and print it directly as Cangjie generics.

Demonstrate the extension with generic identity, `Pair<A, B>`, and `Box<T>` with `map<U>`.

## Implementation

- Add structured source types for primitives, type variables, named type applications, and function types. Define scoped type parameters, substitution, instantiation, and well-formedness checks.
- Add generic declarations and source expressions with explicit declaration references, constructor names, receiver types, and type arguments. Support rank-one polymorphism and callbacks with monomorphic function types.
- Define erasure into existing CJR expressions: type arguments disappear, named calls resolve to existing function terms, and constructors and fields resolve to their declared layouts. Preserve evaluation order and existing recursive-function behavior.
- Prove that type instantiation preserves erasure and that erasure commutes with supported term substitution. Express generic weakest preconditions through erasure and derive safety using existing CJR adequacy.
- Extend extraction with a structured generic printing path. Use explicit references rather than body equality or field-count heuristics. Reject unresolved names, unbound type variables, incorrect arities, and unsupported forms with actionable diagnostics.
- Preserve existing extraction interfaces and monomorphic examples. Add the generic example to aggregate extraction, runtime testing, documentation, and the assumption audit.

## Examples and proof obligations

- **Identity:** prove that the same implementation returns its input uniformly for any element representation.
- **Pair:** prove construction and projections for independently parameterised components.
- **Box:** prove construction, reading, and `map<U>`, with a callback contract relating input and output representations. State ownership requirements explicitly; do not assume arbitrary Iris resources can be duplicated.
- Instantiate examples with `Int64`, `Bool`, and nested generic values. Include a method whose own type parameter differs from its class parameter.

## Validation

- Check substitution, nested instantiation, type-parameter scoping, and erasure laws in Rocq.
- Test extraction failures for invalid references and arities, and disambiguation of declarations with identical bodies or layouts.
- Compile and execute generated generic examples using the repository’s Cangjie 1.0.5 toolchain.
- Run existing runtime suites and extraction regressions, then `make verify`; audit the new public proof results without admissions or added axioms.
- Update the README and tutorial to explain generic syntax, Iris contracts, erasure, and extraction’s remaining trust boundary.

## Assumptions and boundaries

- Keep the current untyped runtime and existing proofs stable. This extension provides uniform Iris specifications, not a general typing-soundness or relational-parametricity theorem.
- Defer interface bounds, inheritance, higher-rank polymorphism, generic raw-memory allocation, and migration of existing containers.
- During implementation, record outstanding human prompts exactly through the repository logging helper, without duplicating existing entries. Preserve existing log changes and refresh the verification log.
